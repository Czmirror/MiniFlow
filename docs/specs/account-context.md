# 管理者本人の更新と画面の所属同期

ユーザー管理で保存に成功したら、応答のユーザー情報を使って画面を同期する。APIのチーム割当・管理者認可は既存契約を維持し、クライアントから変更しない。

- AC1: 本人のteamまたはroleが変わる場合は、旧申請の一覧・集計・選択詳細・承認理由を破棄し、新しい本人情報でダッシュボードへ移る。未保存の作成文面とユーザー作成入力・パスワード入力も消去し、変更通知を示す。保存済みの申請は変更しない。
- AC2: 本人のroleがAdminでなくなったら管理画面を表示せず、管理者専用一覧も再取得しない。Adminのままなら新しい本人情報でユーザー一覧を再取得する。
- AC3: 本人の表示名・言語だけの変更は画面へ反映し、未保存の申請文面は維持する。他人の編集で本人情報と入力を変更しない。
- AC4: 更新失敗は編集内容を残してエラーを表示する。認証失効時は既存のセッション破棄を適用し、その後に届いた更新応答で本人情報を復帰させない。旧所属から遅れて返る申請一覧・詳細の成功と失敗を新しい所属へ適用しない。

入力値の許容条件・認可・エラー形式は`docs/API.md`の既存契約どおり。試験は`docs/tests/functional/account-context.md`と`docs/tests/unit/account-context.md`。2026-10-27、計画提示後の「ok、通常PRまでお願いします」で承認された。
