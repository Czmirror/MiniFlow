# 不要な下書き・差し戻し申請を削除する

## 何ができるようになるか

申請詳細から、不要になった下書きや差し戻し申請を削除できるようにする。APIにある既存の削除機能を画面へつなぐ。削除した申請は通常の一覧とダッシュボードの件数から外れる。画面から元へ戻す機能はない。保存先では既存仕様どおり削除済みとして記録を残し、物理削除しない。

## 使うときの流れ

1. 対象の申請詳細を開き、「この申請を削除」を押す。
2. 確認画面に申請名、「削除後は画面から元に戻せません」「未保存の変更も破棄されます」を表示する。
3. 「キャンセル」なら何も変えず詳細へ戻る。「削除する」なら削除し、元の一覧へ戻って完了を知らせる。

## 受け入れ条件

- DU1: 削除ボタンは、下書き・差し戻しのうち、本人の申請または同じチームの管理者が扱う申請にだけ表示する。承認待ち・承認済み・削除済みには表示しない。サーバー側の既存の権限検査は維持する。
- DU2: 申請名と注意書きを確認してから実行する。キャンセル・Escでは通信せず、未保存の入力も維持する。確認画面の初期focusはキャンセル側とし、閉じたら元のボタンへ戻す。Tab移動を確認する。
- DU3: 成功時だけ削除完了とし、詳細・履歴・未保存入力を破棄する。自分の申請・承認待ちから開いた場合はそれぞれの一覧へ、その他は申請一覧へ戻す。状態フィルターとページ位置は`request-status-filter.md`のLP1〜LP4に従い、一覧と件数を再取得する。
- DU4: 送信中は重複実行を防ぐ。失敗時は詳細を残してエラーを表示し、自動再送しない。409は既存の再取得案内、401は既存のログイン画面への復帰を使う。認証失効や所属・権限変更後の遅い結果が旧詳細や旧一覧を復帰させない。
- DU5: 日英の文言と既存の外観を使い、広い画面・狭い画面・キーボードで操作できる。

既存の認可・状態遷移・論理削除・保存競合の正本は`docs/API.md`。新たな削除API・復元・一括削除・完全削除は作らない。今回の試験は架空のメモリデータだけで、実DBや実際の申請を削除しない。
