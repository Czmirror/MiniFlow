# 申請詳細の読みやすさ

目的は、現在の状態・差し戻し理由・次の操作を迷わず確認できるようにすること。API・入力許容値・認可・保存方式は変えない。

| ID | 受け入れ条件 |
| --- | --- |
| RD1 | 件名と状態が先頭にあり、長い日本語・英語、390pxでも読める |
| RD2 | 現在がRejectedで最新決定がRejectedの場合だけ、理由を本文の前に表示する。空の理由は既存の「理由なし」。履歴なしや別状態は古い理由を現在の指示として表示しない |
| RD3 | 本文の改行を保持して折り返す。文字列をHTMLとして実行しない。Draftの編集条件と未保存確認を維持する |
| RD4 | 状態・本人・roleごとの既存操作だけを説明付きでまとめる。送信中は無効、失敗は入力保持。削除確認と戻るの未保存確認を維持する |
| RD5 | 既存の決定履歴だけを古い順に表示し、同時刻はAPI配列の順を保つ。提出・作成を決定履歴に捏造しない。0件と空の理由を区別する |
| RD6 | 詳細の読込中・未選択・失敗・成功を分ける。失敗から再試行または一覧へ戻れる。401・認証境界変更・古い応答の破棄を維持する |

理由と本文は同一チームの既存閲覧範囲だけで表示する。新しいNGワード基準・リンク化・利用者名の解決は対象外。計画と注釈は`docs/work/harness-refresh-detail-design/plan.md`、絵は同じ場所の`blueprint.html`。2026-10-31作成。同日の会話「マージまで進めて良いです」で計画・設計図・仕様・試験とCanva修正保存を承認済み。
