# 申請一覧の状態フィルター

## 目的と範囲

申請一覧と自分の申請で、必要な状態の申請をページ全体から探せるようにする。APIの既存status条件を使い、表示中の20件だけをクライアントで絞り込まない。状態遷移・認可・保存仕様は変更しない。

## 受け入れ条件

- SF1: 申請一覧と自分の申請に「すべての状態」「下書き」「承認待ち」「承認済み」「差し戻し」の選択欄を置く。初期値はすべて。削除済みは従来どおり表示しない。
- SF2: 条件変更時は1ページ目からサーバーで再取得し、件数とページ送りも絞り込み後のtotalを使う。ダッシュボードの全件集計には条件を適用しない。承認待ち専用画面は既存の条件を維持する。
- SF3: 申請一覧と自分の申請の条件は別々に保持し、同じログイン中は画面移動・詳細からの戻りで維持する。ページ番号は既存どおり画面移動で1に戻る。ログアウト・認証失効・本人の所属または権限変更で条件をすべてへ戻す。言語変更では条件を維持する。URLやブラウザ保存先へは永続化しない。
- SF4: 条件変更前の遅い成功・失敗が新条件の一覧・エラー・読込状態を上書きしない。失敗は0件に見せず、選択条件のまま再試行できる。該当なしでは「条件に一致する申請はありません」と表示し、条件を解除できる。
- SF5: 日本語・英語の既存文言を使い、フィルターのlabel・focus・キーボード操作を提供する。狭い画面で操作を失わない。

入力は画面の固定選択肢だけ。APIへのstatusは既存の列挙値で、すべての場合は送らない。API側の入力検証・本人/チーム境界は`docs/API.md`を維持する。不明な値を任意のqueryへ転送しない。新しいAPI・DB・依存・通知・保存機能は追加しない。

計画の説明後、ユーザーの「よいです」で承認された。
