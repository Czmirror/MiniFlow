# 下書きの未保存入力を失う前に確認する

## 目的と範囲

保存済みの下書き申請を詳細画面で編集しているとき、保存前の件名・本文を誤って失うのを防ぐ。作成画面、アカウント設定、ユーザー管理、承認理由の入力、自動保存・再起動後の復元は今回の対象にしない。

## 受け入れ条件

- UC1: 編集可能なDraftの詳細で、件名または本文が表示中の保存済み内容と異なる間だけ未保存とする。文字列は入力どおり比較し、空白だけの変更も含める。元の内容へ戻した場合は確認しない。
- UC2: 未保存のまま別画面へのナビゲーション、「戻る」、明示的なログアウトを選ぶと確認画面を開く。「編集を続ける」と「変更を破棄して移動する」を用意し、ログアウト時は行き先が分かる文言にする。同じ画面への操作では不要な確認を出さない。
- UC3: 初期focusは「編集を続ける」とし、キャンセル・Escでは入力・画面・選択申請を保って、操作元へfocusを戻す。破棄を選んだ場合だけ意図した移動を1回行う。移動で保存APIを自動実行しない。ログアウトが失敗した場合は詳細と入力を残す。
- UC4: 保存・申請が成功し、その結果が詳細へ反映されたら未保存の確認は不要になる。保存失敗・競合時は入力と確認を維持する。申請の保存・状態変更を送信している間は、確認画面からの移動も含め、通常の画面移動を止める。削除は既存の専用確認だけを使い、確認を二重に出さない。
- UC5: 401による認証失効や本人の所属・権限変更では、既存の安全な画面初期化を妨げず、未保存入力と保留中の移動を破棄する。古い確認画面や操作を新しい認証境界へ引き継がない。保存済み申請とサーバー認可は変更しない。
- UC6: 入力操作後、未保存のままブラウザを再読込・閉じようとした場合、対応ブラウザの標準警告を使う。保存済みなら警告を登録しない。標準警告の文言はブラウザに任せ、ブラウザ終了や障害からの復元は保証しない。
- UC7: 日本語・英語、通常幅・狭い画面、Tab・Enter・Escで確認を操作できる。一覧の戻り先・絞り込み・ページ位置は既存仕様を維持する。

API・DB・migration・権限・入力の許容値は変えない。入力や保留中の移動は表示中のReact状態だけに持ち、URL・ブラウザ保存先・ログ・外部サービスへ保存しない。
