# 申請詳細の機能試験

仕様は`docs/specs/request-detail-readability.md`。架空メモリ保存先と本番HTTPを使い、実DBは操作しない。実施者Codex、2026-10-31。本番Next.js専用コピーとメモリAPIをCUAで操作。

| ID | 条件 | 操作・期待結果 | 結果 |
| --- | --- | --- | --- |
| RD-F1 | RD1 | 長い件名・本文を日英/通常幅/390pxで開き、注釈1/3/8と比較する | 成功 |
| RD-F2 | RD2 | 差し戻し・空理由・履歴なし・過去の差し戻し後の別状態で、現在の理由だけを強調する | 成功 |
| RD-F3 | RD3/RD4 | 本人のDraft/Rejected、他人のPending、閲覧のみで既存の操作条件を維持する。修正から再提出まで通す | 成功 |
| RD-F4 | RD4 | 遅延・失敗で操作無効化/入力保持、削除取消・未保存取消で誤実行がない。Tab/Enter/Escを確認する | 成功 |
| RD-F5 | RD5 | 履歴0件・1件・複数回、空理由、同時刻で正しい順と内容を表示する | 成功 |
| RD-F6 | RD6 | 詳細の遅延・500・401・未選択を確認し、安全な表示と復帰操作を照合する | 成功 |

AI操作と人間の受け入れを区別し、実装後に実施者・日時・証拠を記録する。

RD-F1〜F6は`docs/work/harness-refresh-detail-design/result.md`に操作と証拠を記録した。未選択は通常の入口から到達しないため本番部品のSSR試験で確認し、実ブラウザの未選択画面は未実施。同時刻・日時欠け・差し戻しなのに履歴なしは試験専用APIで架空の応答を返し、正常データの業務遷移とは区別した。AIの実動確認であり人間の画面受け入れではない。
