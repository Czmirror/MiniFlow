# 状態フィルターの機能試験

仕様は`docs/specs/request-status-filter.md`。本番HTTP＋架空メモリ保存先・専用Webで実施し、実DBは使わない。Codexが2026-10-28にIABで実施した。team-1は36件（Draft26/Pending5/Approved3/Rejected2）、本人31件、team-2はDraft4件。Web43106/API43107。

| ID | 対応条件 | 操作と期待結果 |
| --- | --- | --- |
| FF1 | SF1/SF2 | 20件超・複数状態の一覧で状態を選び、先頭ページ外の対象も表示され、totalとページ数が一致する |
| FF2 | SF2 | 2ページ目から条件を変更すると1ページ目へ戻る。ダッシュボード全件数と承認待ち専用画面は変わらない |
| FF3 | SF3 | 一覧ごとに違う条件を選び、詳細と他画面を往復して各条件を維持する。ログアウト/認証失効/所属変更ではすべてへ戻す |
| FF4 | SF3/SF5 | ja/enを切り替え、条件は保持して表示だけ翻訳する |
| FF5 | SF4 | 対象0件の条件と解除、取得失敗と同条件の再試行を確認する |
| FF6 | SF4 | 旧条件の応答を遅延させて新条件へ変更し、旧成功・失敗が画面を戻さないことを確認する |
| FF7 | SF5 | 広い/狭い画面で選択欄・表・ページ送りを確認し、Tab・矢印・Enterで操作できる |

## 実施結果

- FF1/FF2: 成功。Draft26件で1–20、21–26を確認。2ページ目からApprovedへ変更後は1–3/3・1/1。dashboardは全36件・本人31件を維持し、承認待ち専用画面は選択欄なしの5件。
- FF3: 成功。一覧Approved・自分Draftを個別保持し、自分の詳細から戻ると自分の申請のDraftを維持。ログアウトと401失効後に再ログインするとすべてへ戻り、本人team-2変更後もすべての4件へ戻る。role変更単独のブラウザ試験は未実施で、同じidentity/resetのコードを独立レビューで確認した。
- FF4: 成功。ja→enの設定保存後もApprovedを保持し、選択肢と表示が英語へ切り替わる。
- FF5: 成功。自分Pendingは0件の専用文言。Rejectedの503では選択欄とエラー・再読み込みを維持し、障害解除後は同条件2件を表示。「すべて」への解除も可能。
- FF6: 成功。Draft成功、Rejectedの503応答をそれぞれ6秒遅延させ、Approvedへ変更。旧応答到着後もApproved3件を表示し、旧エラー0件。
- FF7: 成功（確認範囲内）。1280pxと390px幅で表示確認。Space→矢印→EnterでApprovedからPendingへ変更し、Tabで表へ移動できる。native selectへのHome/ArrowDownだけの初回操作では変更されず、選択欄を開いて操作した。実機・他ブラウザ・実際の200%拡大は未実施。

console error/warnは0件。画像はGit対象外の`.harness/reports/status-filter-wide.png`と`status-filter-narrow.png`。狭い画面の表とナビゲーションは既存の横スクロールを維持する。AI操作と人間の見た目の受け入れは区別する。
