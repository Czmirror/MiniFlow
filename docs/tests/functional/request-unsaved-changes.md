# 未保存の下書きからの移動確認の機能試験

対象仕様は`docs/specs/request-unsaved-changes.md`。2026-10-28〜29にAIがブラウザを操作した。専用Web・本番HTTP・架空メモリ保存先で実施し、実DBは操作しない。試験の入力は架空データだけを使う。

| ID | 条件 | 操作と期待結果 | 結果 |
| --- | --- | --- | --- |
| UF1 | UC1 | 未編集の詳細は直接戻る。件名・本文を編集すると確認対象になり、元の文字列へ戻せば確認しない。空白だけの変更も試す | 成功。同値・復元は直接戻り、件名末尾の空白で確認した |
| UF2 | UC2/UC3 | 戻る・別画面・ログアウトから確認を開く。「編集を続ける」とEscは入力と画面を保ち、操作元へfocusを戻す。キャンセルで通信しない | 成功。戻る・別画面・ログアウトのキャンセル、Esc、操作元へのfocus復帰を確認した。最初のキャンセル群の後は保存・ログアウトとも0回だった |
| UF3 | UC2/UC3/UC7 | 破棄を選んだ場合だけ指定先へ1回移動する。一覧の条件とページ位置を保つ。ログアウト失敗は詳細と入力を残す | 成功。破棄のダブルクリックでも一覧の下書き条件・2ページ目を保持した。ログアウト503は入力を保持し、正常ログアウト後の再ログインでは旧入力が消えた |
| UF4 | UC4 | 保存・申請後の詳細反映では確認不要。500/409では編集を保持する。送信中の移動を止める。削除は専用確認だけで、キャンセル時は入力を保つ | 成功。保存・申請後は直接戻った。500/409では本文を保持した。10秒遅延の保存中は入力・移動・ログアウトが無効だった。削除確認は1つだけで、成功後は下書き条件の1ページ目へ補正した |
| UF5 | UC5 | 未保存時のAPI操作で401を受け、安全な初期化と再ログイン後の入力破棄を確認する。確認中の所属/権限変更などUIで同時操作できない経路は、保留操作の状態試験と独立レビューに照合し、実動結果と区別する | 成功。保存401で確認を挟まずログインへ戻り、再ログイン後は保存済み本文だけを表示した。同時に所属/権限を変更する経路は単体試験と独立レビューで照合した |
| UF6 | UC6 | 実際の入力後にブラウザ再読込で標準警告が出る。取り消すと入力を保つ。保存反映後は警告なし。端末の未検証範囲を明記する | 成功。Vivaldi本体の再読み込みボタンで標準警告を開き、キャンセル後の本文保持を確認した。同じタブで保存後は警告なしで再読み込みできた（初期試行の制約は結果記録） |
| UF7 | UC3/UC7 | 日本語・英語、通常幅・390pxで文言とボタンを確認する。初期focusは編集継続、Tab・Enter・Escで操作できる | 成功。日英、通常幅・390pxで確認した。初期focusは編集継続、Tabで破棄へ移り、Enterで継続、Escで戻るへfocusが戻った |



環境・証拠・制約は`docs/work/request-unsaved-changes/result.md`を参照する。人間による画面受け入れは未実施。
