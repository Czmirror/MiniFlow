# 申請作成後の復帰単体試験

- 対象: `apps/web/src/lib/requestCreation.ts`の`runRequestCreation`。
- 関連: [仕様書](../../specs/request-create-recovery.md)、[計画](../../work/request-create-recovery/plan.md)。
- 本番処理を直接呼び、通信と世代判定だけを置き換える。

| ID | 観点 | 期待結果 | 対応するtest名 | 結果 |
| --- | --- | --- | --- | --- |
| UT1 | 保存・提出の正常系 | 作成通知が提出より先。作成は1回、提出は選択時だけ1回 | 保存だけなら作成を1回行い、提出を呼ばない／作成を画面へ通知してから同じIDを1回だけ提出する | 成功 |
| UT2 | 作成後の提出失敗・401・409 | 作成済みIDと提出のエラーを区別し、自動再送しない | 提出失敗でも作成済みIDを返し、自動再送しない | 成功 |
| UT3 | 提出応答消失 | 提出済みか断定せず、対象IDを維持する | 提出は完了して応答だけ失われても、未提出と断定しない | 成功 |
| UT4 | 作成失敗・応答破損・401 | 作成済みとして通知せず、提出を呼ばない | 作成応答が得られなければ提出も作成通知も行わない | 成功 |
| UT5 | 世代変更 | 古い開始・作成成功・作成失敗・提出成功・提出失敗は破棄する | 既に無効な操作では通信しない／境界変更後の作成success・failureは破棄し、提出しない／作成通知で境界が変わったら後続の提出を行わない／境界変更後の提出success・failureを新画面へ返さない | 成功 |

- 実行: 2026-11-04、`corepack pnpm test -- tests/apps/web/RequestCreation.spec.ts`。Vitestの実行対象は全29ファイルで、追加15件を含む347件が成功。
- UI側の二重操作拒否、旧finallyが新しい操作のロックを解除しないこと、詳細取得失敗後の再試行は、差分レビューの対象とする。DOM操作での確認は機能試験FT3・FT5に残し、単体成功とは扱わない。
- DBトランザクションは変更しないため新規DB試験は行わない。入力規則は維持し、既存の入力試験を回帰実行する。
