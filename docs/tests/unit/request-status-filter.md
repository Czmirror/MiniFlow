# 状態フィルターの単体試験仕様

本番の選択肢・取得処理・一覧componentを対象とする。Codexが2026-10-28に実行。

| ID | 条件 | 対応テスト | 結果 |
| --- | --- | --- | --- |
| SU1 / SF1 | 解除と4状態だけを許可し、削除済み・未知値を拒否 | RequestStatusFilter: 解除と4状態だけを許可し、削除済み・未知・空白を拒否する | 成功 |
| SU2 / SF4 | 0件と失敗を区別し、選択欄と再試行を残す | RequestStatusFilter: 0件と失敗を区別し、どちらも選択欄を維持する | 成功 |
| SU3 / SF2 | 補正後もstatusとscopeを保持し、全件集計は絞らない | RequestCollection: 補正後もstatusを維持し、全件集計は絞り込まない | 成功 |
| SU4 / SF2 | dashboardにはstatusを送らない | RequestCollection: ダッシュボードは一覧条件を使わない | 成功 |
| SU5 / SF4 | 旧条件の成功・失敗を破棄 | RequestCollection: 条件変更後の遅い応答は成功/失敗とも破棄する、2ケース | 成功 |

追加6ケース。既存のページ補正・0件・無効化・集計失敗の5ケースも維持する。Reactのサーバー描画はWebの既存依存を使い、本番RequestListを呼ぶ。hookの状態寿命は実ブラウザの機能試験で別途確認し、隔離試験の成功で代替しない。
