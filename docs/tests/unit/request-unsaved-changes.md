# 未保存の下書きと移動確認の単体試験

関連仕様は`docs/specs/request-unsaved-changes.md`、計画は`docs/work/request-unsaved-changes/plan.md`。本番が使う状態処理をimportし、テスト用の複製実装は作らない。2026-10-29の最終検証で成功した。入力値と期待値の詳細は実装後のtestコードを正本とする。

| ID | 対象・観点 | 期待結果 | 対応test | 結果 |
| --- | --- | --- | --- | --- |
| UU1 | 保存基準との差分 | 同値・元へ戻すと未保存でなく、件名/本文/空白/改行の変更は未保存になる | 同じ内容と、編集してから元に戻した内容は未保存でない／入力を正規化せず比較する: %j | 成功 |
| UU2 | 申請・認証境界 | 別申請・別本人・所属/権限変更・resetで旧入力と保留操作を使わない | 境界変更では旧入力と保留操作を使わない: %s／別申請・保存結果・非編集画面では旧入力を破棄する／初期化後の確定では旧移動を実行しない | 成功 |
| UU3 | 確認の状態遷移 | 入力なしでは直接移動、変更ありでは保留、キャンセルは保持、確定は意図した操作だけ1回となる | 変更があるときだけ移動を保留し、確定を1回だけ返す: %s／キャンセルでは入力を保ち、移動しない | 成功 |
| UU4 | 保存・送信中・失敗 | 保存結果の反映で基準更新、失敗は保持、送信中に保留操作を実行しない | 同じ保存基準と失敗時には編集を維持する／送信中は移動と保留中の操作を実行しない: %s／別申請・保存結果・非編集画面では旧入力を破棄する | 成功 |
| UU5 | 画面接続と出力 | 本番確認UIの日英の選択肢・安全な初期focus・文言を確認する。入力値をHTMLとして描画しない | 日英の選択肢と初期focus・無効状態を表示し、ログアウト先を区別する | 成功 |

native dialogのfocusとブラウザ標準の離脱警告、通信の成功・失敗は単体試験で代替せず、機能試験で確認する。

対応testはすべて`tests/apps/web/RequestEditor.spec.ts`。UIのSSR検査は文言・構造の確認であり、focusの実動はUF7で確認した。
