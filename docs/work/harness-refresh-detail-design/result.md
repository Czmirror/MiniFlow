## ブラウザでの動作

2026-10-31にCodexがCUAで専用Next.js本番build（localhost:43110）と、本番HTTPを使う架空メモリAPI（43111）を操作した。実DB・実ユーザー・既存の手動確認環境には接続していない。入口はGit対象外の`.harness/reports/detail-fixture.ts`。変更ソースの専用コピーを使い、秘密設定はコピーしていない。検証スキルの流れに沿い、一覧の詳細操作→GET→メモリ保存先→DTO→画面を確認した。

- RD-F1: 通常幅1280pxと390px、日英で長い件名・改行・非常に長い英単語が折り返し、390pxのdocument幅も390px。本文のHTML例は文字のまま表示された。
- RD-F2/F5: 2件の理由がある差し戻し、空理由の1件、Draftの0件、再申請後Pendingを確認。Pendingでは過去の理由を強調しない。同時刻は入力順、日時欠けは「-」で強調なし、差し戻しの履歴欠けも空表示で落ちなかった。後3条件は試験専用応答で作った欠けデータ。
- RD-F3: 本人Rejected→下書き→件名編集→保存→再申請でPendingへ進んだ。他人Pendingには承認/差し戻し、本人Pendingには操作不可の説明、Draftには編集と提出が出た。
- RD-F4: 変更中は操作/移動が無効。保存失敗でも編集値を保持。未保存確認はTabで確定側へ移れ、Escで編集継続。削除確認は取消後に削除ボタンへfocusが戻り、削除は送信していない。
- RD-F6: 遅延中は旧申請を消して読込表示。500で再試行と戻るが出て、再試行でDraftへ復帰。401は申請を消してログインへ戻った。未選択は通常経路に入口がないため本番部品のSSR試験で確認した。

console error/warnは取得ログで0件。HTTPの500/401/503は上記の意図した障害応答で、正常系の障害と区別する。新規CSSの`align-items: start`にビルド警告が出たため`flex-start`へ修正した。レイアウトの意味は同じで、最終buildで再確認する。
証拠はGit対象外の`.harness/reports/detail-wide.png`、`detail-narrow-ja.png`、`detail-narrow-en.png`、`detail-error.png`。未実施は人間の見た目の受け入れ、実機・他ブラウザ・200%拡大。Unity/Godotの実動規則は対象外だが、Web規則のブラウザ検証は上記のとおり実施した。
