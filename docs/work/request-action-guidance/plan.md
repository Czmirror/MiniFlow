# 承認済み申請の案内を完了状態に合わせる

2026-11-24の会話「問題なければマージしてください、引き続き開発お願いしますe2eもお願いします」に基づく。PR #29はCI成功・レビュー指摘なし・未解決threadなしを確認しマージした。fetch済みmain `b7a376d`から別worktreeを作り、ホームページの既存作業を保護する。

前回E2Eの記録に残った、承認済みでも「提出後に承認できます」と表示される問題を直す。既存仕様RD4（現在の状態に対応する操作説明）の不具合修正であり、新たな業務仕様・認可・API・依存・保存方式は追加しない。

1. `RequestDetailActions.approvalUnavailableMessage`でApprovedを先に判定し、「承認は完了しています。追加の承認操作はありません。」を表示する。英語は同じ意味にする。状態・本人・roleによる操作ボタンの条件は保つ。
2. 本番部品の回帰試験で日英・3role・本人/他人を確認し、承認済みには操作ボタンや理由入力がないことを検証する。既存Draft/Pending/Rejected等の試験も維持する。
3. 前回と同じ本番API/Web・固定localhost HTTPS・使い捨てPostgreSQLで承認後とAPI再起動後の案内を確認する。既存21項目も再実行する。専用の空DBへ既存9件のmigrationと架空4ユーザーを投入し、終了後に専用環境を削除する。
4. Profile・最終差分レビュー後に通常PRへまとめる。新規PRはマージせずレビュー可能な状態に残す。

既存component内の表示説明だけを変更し、新しい層を作らない。文言は既存`messages.ts`を正本にする。UIは既定B、既存の配置・CSSを保つ文言修正のため設計図は不要。追加の仮の数値なし。機能仕様は既存`docs/specs/request-detail-readability.md`を参照し、試験仕様へ観点を追加する。

Admin screens/Display states→承認済みと提出前を区別する説明を部品試験と実画面で確認。Database/Sensitive data→既存の専用固定DBと架空データだけを使用し、秘密を証拠へ保存しない。ブラウザの外部通信拒否と未知エラー検査を維持する。
