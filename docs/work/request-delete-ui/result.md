# 申請削除画面の実装・検証記録

## 概要

不要な下書き・差し戻し申請を詳細から削除できるようにした。
申請名と元に戻せない旨を確認し、確定したときだけ削除する。
実装と架空データでの操作確認を終えた。所属変更と削除応答の同時操作はブラウザで未確認であり、コードの独立レビューで補っている。
人間による画面の受け入れ確認は未実施。

## 実装と設計

- 基点は`e9c1d598e413aa0ebd984eda8b4c6d62d535a7f1`。仕様は`docs/specs/request-delete-ui.md`、承認済み計画は同じ作業フォルダーの`plan.md`。
- 確認画面は`RequestDeleteAction`、表示条件は`canDeleteRequest`へ分けた。親画面が通信・結果反映・画面寿命を担当する。
- 同期的な送信ロックと既存の認証・詳細の世代比較で、重複送信と古い結果の反映を防ぐ。成功時だけ詳細を破棄し、元の一覧の条件を保って再取得する。
- 文言は既存の日英辞書へ追加した。外観は既存tokenを使い、仮の調整値は追加していない。
- API・DB・migration・依存・Harness正本は変更していない。実DBへの適用や実データ削除は行っていない。

- 文章形式、TypeScript、全24ファイル260試験、API/Web本番build、secretsは成功した。lintは既存設定未整備のためRunnerでskipped。
- 最初の追加試験はHTML属性名の期待違いで1件失敗した。期待を修正後、全体試験で成功した。失敗ログも保存している。
- 単体試験仕様は`docs/tests/unit/request-delete-ui.md`、機能試験仕様は`docs/tests/functional/request-delete-ui.md`。実動の成功・未実施範囲は後者に明記した。

## 最終差分レビューと承認

削除の権限・認証境界について独立AIレビューを実施した。表示条件、成功・失敗・finallyの世代比較、一覧hookを確認し、実装上の明確な不具合は見つからなかった。単体試験仕様とソースの地図が未作成という文書指摘2件は追記し、再レビューで解消と指摘なしを確認した。コメントと責務の分離も照合し、分割延期や承認範囲外の変更はない。自己レビューでも最終差分と承認済み仕様を照合した。

人間の承認は会話で提示した計画・仕様への「よいです」。通常PRの作成と、レビュー・チェックに問題がなければマージする指示を受けている。実データ削除は承認範囲に含めない。新規セッションでのルール読み込みや承認前停止などの運用全体は自動試験していない。

残存リスクは所属変更と削除応答の同時操作のブラウザ未確認、および既存のlint未整備。範囲外の新たな問題はなし。人間による画面確認は未実施で、状態は実装・AI検証済み。PRのレビューとチェックを監視し、条件を満たした場合にマージする。
