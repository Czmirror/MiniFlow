# Spec draft: 申請一覧と全件集計

目的は、21件以上の申請を見落とさず、件数をページサイズに依存させないこと。
API契約の正本`docs/API.md`への反映案。承認前の草案であり、現在の実装を示すものではない。

- AC1: 申請一覧・自分の申請・承認待ちは、用途に合う申請を20件ずつ表示し、前後のページへ移動できる。画面に表示範囲と総件数を示す。
- AC2: 自分の申請と承認待ちは、ページ取得前にサーバーで本人・チーム・状態を絞る。Applicantの承認待ちは0件。既存の参照権限は変更しない。
- AC3: ダッシュボードの6指標は同一teamの削除済み以外の全件から算出する。承認待ちの表は自分以外のPendingの先頭5件で、Applicantには空表示を維持する。
- AC4: 一覧の切り替えは1ページへ戻り、更新後の空の最終ページは有効ページへ補正する。失敗時は再読み込みでき、未取得を0件と表示しない。古い応答は新しい認証・画面へ適用しない。
- AC5: 未認証は401、未知scope・不正ページ・矛盾するscope/statusは400。他teamや任意の本人をクライアントから指定できない。
- AC6: 390 pxと1280 pxでページ操作が見え、キーボードで移動できる。既存の状態ラベルと外観を維持する。

API追加案はGET `/requests?scope=all|mine|pendingApprovals`とGET `/requests/summary`。詳細な入力条件、後方互換、並び順、同時更新時の限界は`plan.md`を参照する。業務検索・並び替え・通知・DB構造変更は対象外。

承認: 計画提示後の会話「ok」で採用された。現行の契約は`docs/API.md`へ反映済み。最終更新2026-10-27。
