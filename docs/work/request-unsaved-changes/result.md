# 未保存の下書きの移動確認：実装と検証

## 概要

保存済み下書きの件名・本文に変更がある場合、戻る・別画面・ログアウトの前に確認する。
うっかり入力を失うことを減らし、編集継続と破棄を選べるようにした。
保存失敗時は入力を残し、認証切れや所属・権限の変更時は安全な初期化を優先する。
人間の画面受け入れは未実施。追加で判断をお願いする事項はない。

基点は`5317a43f90dc427308ea338e2a0aed58c0aad8e7`。対象は`codex/request-unsaved-changes`の今回の差分。関連Issueはない。

- `MiniFlowApp.tsx`は既存APIと移動を接続する。送信中の移動を止め、古い認証境界の完了が新しい入力や操作ロックを消さないようにした。旧詳細部品の編集状態は削除した。

仕様は`docs/specs/request-unsaved-changes.md`。計画は同じディレクトリの`plan.md`。試験は`docs/tests/functional/request-unsaved-changes.md`と`docs/tests/unit/request-unsaved-changes.md`に記録した。API・DB・migration・依存の変更はない。仮の調整値はない。取り消しは今回の変更のrevertで行える。

## 実動検証

2026-10-28〜29にAIがCUAで操作した。最終ソースを複製した専用Next.js開発サーバー（localhost:43110）と、本番HTTP処理を使うメモリfixture（43111）を接続した。架空の本人・下書きだけを使い、実DBは操作していない。

- UF1〜UF3：同値・復元時は直接戻る。空白変更で確認する。戻る・別画面・ログアウトのキャンセルは入力とfocusを保持した。最初のキャンセル群の通信カウンターは保存0回・ログアウト0回。破棄のダブルクリック後も下書き条件・2ページ目を保持した。ログアウト503は入力を保持し、成功後の再ログインは保存済み本文だけを表示した。
- UF4：500/409の保存失敗は入力を保持した。10秒遅延の保存中は入力・移動・ログアウトを無効にした。保存・申請成功後は追加確認なしで戻った。末尾空白が保存時に正規化され同じ保存基準へ戻る場合も確認は残らなかった。削除は専用確認だけを表示し、キャンセルで編集を保持した。架空データ1件の削除後は下書き条件を保持し、最後の2ページ目から1ページ目へ補正した。
- UF5：未保存の保存操作に401を返すと、確認を挟まずログインへ戻った。再ログイン後は旧入力・保留操作がなかった。確認を開いたままの所属・権限変更はUIが同時操作を許さないため、状態試験と独立レビューで照合した。これは実動成功とは区別する。
- UF7：日英と通常幅・390pxで文言とボタンを目視した。編集継続への初期focus、Tabによる破棄への移動、Enterによる継続、Escと操作元へのfocus復帰を確認した。画面幅設定は解除した。

証拠は`.harness/reports/unsaved-confirm-wide.png`（日本語・通常幅）と`unsaved-confirm-narrow-en.png`（英語・390px）。AIが両方を画像として目視した。ブラウザの最終warn/error取得は0件だった。意図的な500/409/401/503は上記の失敗経路の検証であり、本番障害ではない。

### ブラウザ標準警告の確認範囲

UF6は最終的に同じVivaldiの検証用タブで連続確認した。実際に本文へ`Native cancel verified fixture`を入力し、ブラウザ本体の再読み込みボタンを押した。「このサイトを再読み込みしますか？」という標準警告と「キャンセル」「再読み込み」の選択肢をnative画面で観測した。警告へ操作対象を合わせ直して「キャンセル」を押し、同じ詳細と入力本文が保持されたことをnative画面とタブの両方で確認した。

その後「Save Changes」で保存成功を確認し、同じブラウザの再読み込みボタンで警告なしにダッシュボードへ戻ることを確認した。取消後の証拠は`.harness/reports/unsaved-native-cancel.png`。画像としても目視した。

最初のタブ操作APIによる試行では、標準警告イベントは取れても自動で閉じられ、取消操作が失敗した。この試行を成功扱いせず、上記のブラウザ本体の操作で補完した。アプリ内ブラウザでも入力保持と保存後の再読込を確認した。モバイル端末の閉じる操作は未検証。ブラウザ警告は端末制約があり、障害終了時の復元は提供しない。
