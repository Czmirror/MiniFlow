## 対象と判断

既定の見た目水準B（共有・デモ用）を採用する。既存の濃紺・深緑の方向を保つ。第一段階では共通の外観、ログイン、ダッシュボード、一覧を重点的に整え、作成・詳細・設定・管理にも同じ見た目を適用する。

API、DB、認可、チーム所属、申請の状態遷移、入力の許容条件を変えない。検索、通知、グラフ、メール招待などの新機能は含めない。新規依存や外部フォントも追加しない。申請作成や詳細表示は現在の画面内移動を使う。

Canvaはユーザーが指定したツールとして、架空の文言だけを使う編集可能な外観案を作成する。実データ、ソース、認証情報、ローカル画像は送らない。成果物は外観の参考にし、画像や生成コードは取り込まない。モックの例示件数・表示項目を業務仕様にしない。

## 実装案と責務

1. `apps/web/app/globals.css`: 全画面の色・寸法・フォーカス・狭い画面の表示を担当する。既存クラスを使い、変数を正本にして直書きを置き換える。
2. `apps/web/src/components/MiniFlowApp.tsx`: 既存の画面操作を維持し、見出しのまとまり、現在地の意味付け、操作の並びを整える。既存の集計、ナビゲーション、状態ラベル、APIハンドラを再利用する。表示変更のための新しい状態や通信を追加しない。
3. `apps/web/app/layout.tsx`: 言語・フォントの現状を確認し、必要な表示上の補正に限定する。
4. 仕様・試験・結果を同じ作業記録に残す。ソースの役割やファイルを変える場合のみステアリングの地図も更新する。

現在の単一コンポーネントには画面と操作が集まっているが、今回はハンドラや通信の再構成を同時に行わない。表示用の分割が必要になり責務・依存や状態の流れを変える場合は、別案として計画を更新する。処理の流れ・状態遷移・DB・信頼境界を変更しないため、今回の設計図は適用外。

## 仮の調整値

以下はAIが選ぶ初期値であり、実画面を確認して調整する。CSS変数に集約する。

| 項目 | 初期値 | 理由 |
| --- | --- | --- |
| 背景 / パネル | `#f5f7f9` / `#ffffff` | 情報面の区切りを静かに示す |
| 主文字 / 補助文字 | `#182735` / `#526477` | 小さい補助文字の視認性を確保する |
| サイドバー / 主操作 | `#162735` / `#0c6f62` | 既存の方向を保つ |
| 余白 | 4 / 8 / 12 / 16 / 24 / 32 / 48 px | 段階を限定する |
| 基本文字 / 見出し | 16 / 28 px | 操作と見出しに差を付ける |
| 角丸 | 8 / 12 px | 入力と情報面でそろえる |
| サイドバー幅 | 248 px | 主領域の幅を確保する |
| 狭い画面の指標 | 原則2列、内容が収まらない場合1列 | 一覧までの距離を短くする |
